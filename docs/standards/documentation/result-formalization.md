# Result Formalization & Conversation Governance

Maturity: CANDIDATE  
Version: 0.1.0

## Rule
Any conversation that produces a material operating result MUST persist that result in governed documentation before the work is considered closed.

A material result includes decisions, standards, roadmap or milestone changes, financial assumptions, lifecycle/status changes, offers, branding/publication decisions, architecture/tooling/data-model decisions, risks, gates, exceptions and evidence that changes what ADÜMÜN may truthfully claim or do.

## Conversation output
The conversation should remain a concise operating summary. It should state:
1. the important result;
2. material consequences/blockers;
3. the exact document/registry/dashboard/repository path updated or created;
4. sponsor intervention required, if any.

The conversation is never the sole source of truth for a material result.

## Artifact routing
- Human canon/policy/standard/roadmap: Google Docs.
- Live structured operational state/dashboard: Google Sheets.
- Versioned standards/schemas/templates/registries/executable governance: GitHub.
- Product-specific implementation: owning repository.
- Evidence: Evidence Registry and/or owning evidence location.

## Dual representation
If a result changes operational state it requires:
- human-readable context where policy/rationale matters; and
- machine-readable representation suitable for deterministic processing.

## Completion criteria
A material result is FORMALIZED when authority destination, structured state, stable IDs, source-of-truth, version/timestamp/maturity and conversation links are all present as applicable.

## Quick Start freshness
If a material result invalidates a Quick Start, update it in the same workstream or mark it STALE with an explicit follow-up.

## Emergency exception
Emergency decisions may precede documentation only when delay would create greater harm. Backfill documentation at the earliest safe point and record the exception.
