# Quick Start Documentation Standard

- Maturity: CANDIDATE
- Purpose: enable a human or agent to recover operating context in approximately five minutes.

## Required sections
Every Quick Start SHOULD contain:
1. purpose and scope;
2. current status;
3. invariant decisions;
4. authoritative human sources;
5. machine-readable/processable sources;
6. current priorities;
7. gates, stop rules and forbidden assumptions;
8. dependencies/interfaces;
9. stable IDs and controlled vocabulary;
10. where to continue work;
11. invalidation/update triggers.

## Authority
A Quick Start is navigational and explanatory, not canonical. If it conflicts with a canon, financial baseline, approved standard or live registry, the authoritative source wins and the Quick Start must be updated.

## Processability
Quick Starts SHOULD link stable IDs and registry paths so agents do not need to parse prose to determine current state.

## Change control
Material Quick Start changes use branch + PR and preserve links to the human authority they summarize.
